## 3. Wykrywanie zmian kontraktu

`node scripts/check-openapi-drift.mjs` pobiera trzy oficjalne pliki OpenAPI i porównuje je z kopiami w repozytorium (hash + różnice w operacjach: dodane, usunięte, nowo oznaczone jako deprecated). Workflow `openapi-drift.yml` uruchamia to co tydzień i **otwiera zgłoszenie** — nigdy nie zmienia kodu SDK ani nie wydaje wersji. Aktualizacja kopii (`--update`) jest świadomym krokiem, po którym trzeba uruchomić wszystkie testy, łącznie z testami live na TEST.

EN: weekly drift detection reports changes in an issue; it never auto-updates the SDK.

## 4. Metody uwierzytelniania — stan prawny tokenów KSeF (stan na 2026-11-13)

Sytuacja jest **niejednoznaczna**, dlatego dokumentujemy ją wprost:

- Strona MF o certyfikatach KSeF oraz sierpniowa wersja Podręcznika KSeF 2.0 mówią, że po decyzji Ministerstwa Finansów token KSeF będzie utrzymany bezterminowo (do odwołania przez użytkownika).
- Starsze materiały i obowiązujące rozporządzenie (Dz.U. 2025 poz. 1815, § 13, według zgłoszenia [CIRFMF/ksef-api#834](https://github.com/CIRFMF/ksef-api/issues/834)) wskazują 31.12.2026; w obiegu jest też projekt nowelizacji z datą 30.11.2027. Nie potwierdziliśmy publikacji aktu zmieniającego.
- **Wniosek dla użytkowników SDK:** SDK obsługuje obie metody (token KSeF i certyfikat Authentication). Przed poleganiem wyłącznie na tokenie sprawdź aktualny komunikat MF i Dziennik Ustaw. Dla nowych integracji produkcyjnych zalecamy **certyfikat KSeF (Authentication)** jako ścieżkę niezależną od tej decyzji — MF również zaleca ją na PROD ze względu na brak oczekiwania na OCSP/CRL.

EN: token longevity is legally unsettled (MF announces indefinite validity; the in-force regulation text still says 31 Dec 2026). The SDK supports both token and certificate auth; prefer certificates for new production integrations.
