## Before publishing

1. **Add the verified test results link.** The drafts deliberately state no test counts. Link the current report (`docs/dev/test-report.md`) where the drafts say so.
2. **Check every claim against the repository at the commit you tag.** Facts come from `README.md`, `docs/api-compatibility.md`, `docs/dev/findings-live-test.md`, `docs/dev/fa3-scope.md`.
3. **Install status.** The drafts say the npm packages are published and the Composer packages are not yet on Packagist. If that changes before you post, update every file.
4. **Respect each community's self-promotion rules** (Reddit, Dev.to, Discord/Slack servers, Facebook groups). Read the rules, disclose that you are the author, and answer questions.
5. **Never invent adoption numbers.** The drafts contain no user, download or star counts. Keep it that way.
6. Contact points are only the GitHub profile (https://github.com/mysterekkk) and the repository issues (https://github.com/mysterekkk/ksef-foundry/issues). No website or email exists.
