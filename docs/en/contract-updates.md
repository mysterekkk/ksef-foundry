# OpenAPI contract updates

The SDK's behaviour follows the official KSeF API 2.0 contract (the OpenAPI and the Ministry of Finance guide), not guesswork. This guide describes how the project detects contract changes and how to roll them out safely. It is aimed mainly at people maintaining or extending the repository; SDK users will learn from it what "verified against 2.9.0" means.

## Detecting changes

The script `scripts/check-openapi-drift.mjs` (Node >= 22):

```bash
node scripts/check-openapi-drift.mjs            # compare; exit code 1 on a change
node scripts/check-openapi-drift.mjs --update   # refresh the copies and manifest (after code and test changes!)
```

What it does:

1. It downloads the three official OpenAPI files (`https://api-test.ksef.mf.gov.pl/docs/v2/openapi.json`, and likewise DEMO and PRODUCTION). It contacts only those three official hosts and performs read-only GET requests.
2. It compares the SHA-256 hash of each file with the repository copy. Each environment is compared **separately**: we do not assume TEST and PRODUCTION run the same version.
3. For changed contracts it lists operations that were **added**, **removed** and **newly marked deprecated**.
4. Exit codes: `0` no change, `1` drift detected, `2` a file could not be downloaded.

The GitHub Actions workflow `OpenAPI drift` (`openapi-drift.yml`) runs the script **weekly** (Monday 07:00 UTC) and on demand. On code `1` it **opens an issue** labelled `api-drift` with the script output; on code `2` it fails. **It never changes SDK code or cuts a release.**

## Update procedure

Following `CONTRIBUTING.md`:

1. **Run the script** and read its output and the `api-drift` issue.
2. **Read the MF changelog** (the `CIRFMF/ksef-api` repository, the `api-changelog.md` file, and the guide in the `docs` folder) and the difference between the files. The script shows only operations; check schema-level changes (fields, enums, headers) by diffing the files by hand.
3. **Implement** the changes in both SDKs: PHP and TypeScript must behave identically (same names, same retry rules, same error model). Do not call operations marked deprecated. Regenerate the TypeScript types with `npm run generate:types` (it generates from `schemas/openapi/test.json`).
4. **Update the XSD schemas** if FA(3) or the authentication schema changed: the official files import schemas remotely, so the local copies are generated by `scripts/resolve-xsd.php` (it rewrites only `schemaLocation`; checksums are in `SHA256SUMS.txt`). Remember that the XSD copies in the TypeScript package must be byte-identical to PHP's.
5. **Run all tests**: unit, contract, fault-injection, framework and **live on TEST** ([Testing](testing.md)). A `SKIPPED` live result is not a success.
6. **Refresh the copies** with `node scripts/check-openapi-drift.mjs --update` and run the tests again.
7. **Update the documentation:** `docs/api-compatibility.md` (versions, dates, sums), this documentation (PL and EN) and `CHANGELOG.md`. Public API changes need a CHANGELOG entry and a rationale; do not rename public symbols between releases, add new ones.
8. Open a small, focused pull request that says "what and why".

## What the script does not do

- It does not update the SDKs or cut a release.
- It does not compare changes inside schemas; that is a manual step.
- It does not check changes to the invoice XSD (FA(3)) or the authentication XSD; track those through MF announcements and the changelog.
- It does not prove the SDK is compatible with a new version; only updated tests, including live ones on TEST, do.
- Running `--update` without prior code and test changes would leave the repository with a contract copy the SDK does not handle. Use it deliberately.
